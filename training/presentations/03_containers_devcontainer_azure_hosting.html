Containers / Azure hosting
Prečo kontajnery

Problém nie je iba nasadenie, ale rozdielne prostredia

Typická bolesť

  • aplikácia funguje u jedného vývojára, ale inde nie;
  • lokálne nastavenie je dlhé a krehké;
  • rozdiely medzi dev, test a produkciou sa hľadajú ťažko.

Čo prinášajú kontajnery

  • prostredie je popísané v kóde;
  • rovnaký image sa dá spustiť opakovane;
  • závislosti aplikácie sú izolované od hosta.
Containers / Azure hosting
Základná definícia

Kontajner je proces s vlastným izolovaným prostredím

Kontajner nie je malý virtuálny stroj. Je to spustený proces, ktorý používa jadro hostiteľského operačného systému, ale má izolovaný filesystem, sieť, premenné prostredia a závislosti.

Dockerfile

Dev Container

Dev Container štandardizuje vývojársky workstation

Čo rieši

  • rovnaké verzie tooling-u;
  • rýchle onboarding prostredie;
  • menej rozdielov medzi vývojármi.

Čo nerieši

Containers / Azure hosting
Rozhodnutie pre túto appku

Unified Work Items: Azure Functions Flex, nie Container Apps

Prečo Flex

  • malá interná aplikácia;
  • API workload;
  • serverless prevádzkový model;
  • bez potreby vlastného runtime image.

Prečo nie Container Apps

  • nepotrebujeme vlastný image;
  • nepotrebujeme Dapr, sidecars ani revisions ako primárny dôvod;
  • nechceme zbytočnú zodpovednosť za image lifecycle.

Containers / Azure hostingCvičenie · scenár
Cvičenie · 1/3

Spusť existujúci image a pozri sa na životný cyklus

Spusti a over

docker pull nginx:alpine docker run --name web-base \ -p 8080:80 nginx:alpine docker ps docker logs web-base

Otvor http://localhost:8080. Vysvetli si, čo znamená mapovanie 8080:80.

Zastav a odstráň

docker stop web-base docker ps docker ps -a docker rm web-base
  • image zostáva lokálne;
  • container už neexistuje;
  • z toho istého image môže vzniknúť ďalší container.
Containers / Azure hostingCvičenie · lifecycle
Cvičenie · 2/3

Vytvor prvý vlastný image

Priprav dva súbory

# index.html <h1>My first container</h1> <p>Created by: YOUR_NAME</p> # Dockerfile FROM nginx:alpine COPY index.html /usr/share/nginx/html/index.html

Build a run

docker build -t ticket-lab:v1 . docker run --name ticket-lab \ -p 8080:80 ticket-lab:v1 docker images docker ps

Znovu otvor http://localhost:8080. Tentoraz stránku servuje image, ktorý si práve vytvoril.

Cvičenie · 3/3

Dokáž si, že bežiaci container sa sám nezmení

Experiment

  1. Zmeň text v index.html.
  2. Refreshni prehliadač — stále vidíš starú verziu.
  3. Vytvor nový image ticket-lab:v2.
  4. Zastav a odstráň pôvodný container.
  5. Spusť nový container z v2.

Príkazy

docker build -t ticket-lab:v2 . docker stop ticket-lab docker rm ticket-lab docker run --name ticket-lab \ -p 8080:80 ticket-lab:v2 docker images

Cleanup: docker stop ticket-lab && docker rm ticket-lab. Diskusia: prečo je rovnaký nemenný image výhodný pri CI/CD a nasadzovaní do cloudu?
