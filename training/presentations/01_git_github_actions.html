Prečo GitHub

GitHub nie je len úložisko kódu

Git ukladá históriu zmien. GitHub nad tým pridáva pracovný priestor pre tím: plánovanie, diskusiu, kontrolu kvality, automatizáciu a prehľad o tom, čo sa do aplikácie dostalo.

Bez spoločného procesu

  • zmeny sa spätne ťažko vysvetľujú;
  • nasadenie závisí od konkrétneho človeka;
  • kontrola kvality často prichádza až na konci.

S GitHub workflowom

  • každá zmena má kontext, autora a históriu;
  • review a kontroly prebehnú ešte pred merge;
  • repozitár je čitateľný pre ľudí aj AI agentov.

GitHub ako platforma

Základné časti, ktoré budeme používať

Code

Súbory, história, vetvy a základný prehľad o projekte.

Issues

Miesto, kde sa popíše problém, požiadavka alebo plánovaná zmena.

Pull Requests

Kontrolovaný návrh zmeny: diskusia, review, CI výsledky a merge.

Actions

Automatizácia buildov, testov, validácie a neskôr aj deploymentu.

Ďalšie možnosti ako Projects, Releases alebo Security sa dajú zapojiť podľa potreby, ale základný pracovný tok stojí hlavne na Code, Issues, PR a Actions.

Repozitár

Repozitár je miesto, kde žije projekt

Kód a dokumentácia

Aplikačný kód, testy, skripty, štandardy, ADR a produktový kontext.

História rozhodnutí

Commity, PR a prepojené issues pomáhajú pochopiť, prečo zmena vznikla.

Pravidlá práce

Branch protection, CODEOWNERS, PR template, CI a agent instructions chránia spôsob vývoja.

V našom projekte je dôležité, že aplikačný repozitár nerieši Terraform infraštruktúru. Tá patrí do samostatného infra repozitára.

Pull request

Dobrý PR šetrí čas reviewerovi aj budúcemu tímu

Čo sa mení?

Rozsah má byť pochopiteľný bez čítania celej histórie chatu.

Prečo sa to mení?

Prepojenie na issue, ADR alebo štandard drží rozhodnutia na jednom mieste.

Ako je to overené?

CI, lokálne testy, manuálna kontrola alebo jasné priznanie, čo overené nebolo.

Review

Review nie je iba hľadanie chýb v kóde

Technická kontrola

  • správne hranice modulov;
  • testovateľnosť a čitateľnosť;
  • bezpečnosť, konfigurácia a observability.

Kontrola rozhodnutí

  • súlad s issue a plánom;
  • súlad s ADR a štandardmi;
  • žiadne neodsúhlasené rozšírenie scope.

V tomto repozitári má review chrániť aj dokumentačnú disciplínu: jedna autoritatívna informácia, bez zbytočného duplikovania.

GitHub Actions

CI/CD je súčasť vývojového modelu

CI

Beží pri pull requeste a po merge do main. Cieľom je zachytiť chyby skôr, než sa zmena stane základom pre ďalšiu prácu.

CD

Aktuálne cieli len na dev prostredie. Produkčné nasadenie je budúca téma, pravdepodobne cez tagy a releases.

Workflowy nemajú nahrádzať premyslený proces. Majú ho robiť opakovateľným, viditeľným a menej závislým od manuálnych krokov.

Security baseline

Workflow má mať len také práva, aké potrebuje

Pre CI dnes stačí

permissions: contents: read

Pre deployment neskôr

Oddeliť build, release a deployment. Použiť GitHub Environments, tajomstvá alebo OIDC podľa konkrétneho deployment modelu.

Bezpečný workflow je taký, ktorý nerobí viac, než musí. Práva sa pridávajú až vtedy, keď ich konkrétny krok naozaj potrebuje.

Governance

Main musí byť chránený

Ak main nie je chránený, proces je iba odporúčanie, nie kontrolný mechanizmus.

Nastavenie branch protection nie je kódová zmena, ale je to kľúčová časť repozitárového governance.
