Prečo GitHub

Zmena už nie je súbor na disku, ale overiteľný príbeh

Typický on‑prem vývoj

  • zmeny sa ťažko spätne vysvetľujú;
  • nasadenie závisí od konkrétneho človeka;
  • kontrola kvality je často až na konci.

Repo‑driven vývoj

  • každá zmena má issue, branch, commit a PR;
  • review aj CI prebehnú pred merge;
  • história je použiteľná pre ľudí aj AI agentov.

Pull request

PR má odpovedať na tri otázky

Čo sa mení?

Rozsah má byť pochopiteľný bez čítania celej histórie chatu.

Prečo sa to mení?

Prepojenie na issue, ADR alebo štandard drží rozhodnutia pokope.

Ako je to overené?

CI, lokálne testy, manuálna kontrola alebo jasné priznanie, čo overené nebolo.

GitHub Actions

CI/CD je súčasť vývojového modelu

CI

Beží pri vytvorení / aktualizácii PR a po merge do main. Cieľ: zachytiť chyby pred tým, ako sa zmena stane základom pre ďalšiu prácu.

CD

Aktuálne cieli len na dev prostredie. Produkčné nasadenie je budúca téma, pravdepodobne cez tagy a releases.

Dôležité rozhodnutie

Main musí byť chránený

Ak main nie je chránený, proces je iba odporúčanie, nie kontrolný mechanizmus.

Nastavenie branch protection nie je kódová zmena, ale je to kľúčová časť repozitárového governance.
