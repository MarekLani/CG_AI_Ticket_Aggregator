Architektúra
Hranice riešenia

Každá časť má jednu zrozumiteľnú zodpovednosť

Connectors

Komunikujú s konkrétnym zdrojom a mapujú jeho dáta.

Application

Obsahuje zdrojovo neutrálny model a aplikačné use-cases.

API

Poskytuje stabilný HTTP kontrakt pre klienta.

Frontend

Zobrazuje údaje, filtre a používateľské stavy.

Dôležitá hranica: Azure/Terraform infraštruktúra sa implementuje v samostatnom infra repozitári. Tento repozitár definuje iba potreby aplikácie.
Modulárny návrh
Backend

.NET 10 + Azure Functions: jednoduchý backend bez zbytočnej platformovej vrstvy

.NET 10

Silné typovanie, DI, async I/O a dobrá izolácia integračných hraníc.

Functions isolated

HTTP API dnes, neskôr aj timer/background spracovanie bez zmeny aplikačného modelu.

Tenké triggery

Function iba prijme vstup a zavolá aplikačnú logiku. Biznis pravidlá v nej nežijú.

Hosting je technický detail okolo aplikácie, nie dôvod viazať doménový model na Azure Functions.

Technologická voľba
Frontend

React + TypeScript s knižnicami, ktoré majú jasnú úlohu

React + TypeScript + Vite

Základ SPA, strict typovanie a rýchly development/build workflow.

Aplikačné stránky a komponenty bez vlastného frameworku navyše.

Material UI + Data Grid

Hotové UI komponenty a tabuľka vhodná pre dátovo orientovaný pracovný pohľad.

Nemá zmysel budovať vlastný component library ani grid.

TanStack Query

Načítanie serverových dát, cache, loading/error stavy a invalidácia.

Server state neriešime cez ad-hoc globálny store.

React Router

Routing a URL stav tam, kde má byť navigácia alebo filter zdieľateľný odkazom.

Frontend komunikuje iba s naším HTTP API.
Technologická voľba
Platformové rozhodnutia

Dôležité technológie, ale nie samostatné „svety“

Entra ID

Prihlásenie používateľa, tokeny pre API a managed identity pre Azure workloady.

Application Insights

Frontend a backend telemetry sú oddelené, ale korelované cez trace context.

Automatické testy

xUnit pre backend, Vitest/RTL pre frontend a Playwright pre vybrané E2E scenáre.

PostgreSQL neskôr

Databázu pridáme až keď vznikne konkrétna potreba cache, synchronizácie, histórie alebo app-owned stavu.

Roadmapa · ďalšie zdroje

Planner a GitHub majú byť dôkazom, že architektúra funguje

Celok G · Planner connector

Načítať Planner cez Microsoft Graph, explicitne namapovať do rovnakého WorkItem modelu a pridať zdroj do existujúceho zoznamu.

Celok H · GitHub Issues connector

Načítať GitHub Issues, namapovať do rovnakého modelu a využiť existujúci API/UI kontrakt bez GitHub-specific logiky vo frontende.

Architektonický test: ak pridanie nového zdroja vyžaduje prepis základného UI alebo aplikačného modelu, hranice sme navrhli zle.
Rozširovanie riešenia
Persistence až keď ju potrebujeme

Databáza je samostatný implementačný celok iba vtedy, keď rieši konkrétny problém

Prvá verzia

Helpdesk → connector → WorkItem → API → React. Bez aplikačnej databázy.

Možný ďalší celok

PostgreSQL + EF Core až pri cache, scheduled synchronizácii, histórii, agregáciách alebo app-owned používateľskom stave.

Aj potom zostávajú Helpdesk, Planner a GitHub systémami záznamu. Persistence v aplikácii nie je migrácia zdrojových systémov.

Funguje

Acceptance criteria sú splnené a výsledok sa dá reálne overiť.

Je overený

Je reviewovateľný
