Application stack
Identity

Identitu riešime cez Microsoft Entra ID

  • OIDC pre interaktívne prihlásenie používateľa.
  • OAuth 2.0 tokeny pre chránené API.
  • Delegated access pri operáciách v mene používateľa.
  • Application access pre neinteraktívne integrácie a workloady.
  • Managed identities pre Azure service-to-service komunikáciu, kde je to možné.

Application stack
CI/CD

Najprv kvalita a dev deployment, produkcia neskôr

Teraz

CI beží na PR a po merge do main. CD beží iba pri push do main a cieli na dev prostredie.

Neskôr

Produkciu pridáme až s jasným release mechanizmom, typicky cez tag/release a samostatné schválenie.

Main má byť chránený integračný branch. Práca prebieha cez krátko žijúce feature branche a reviewované PR.

Application stack
Azure hosting

Hosting vyberáme podľa workloadu, nie podľa módy

Unified Work Items

Backend cieli na Azure Functions Flex. Pre túto malú internú API aplikáciu je to prirodzenejší model než vlastný runtime container.

Iné workloads

Azure Container Apps dávajú zmysel tam, kde je container image skutočný deployment artefakt a potrebujeme jeho životný cyklus prevádzkovať.

Application stack
AI-assisted workflow

AI má pomáhať s implementáciou, nie rozbíjať rozhodnutia

  • Issue zachytáva cieľ, hranice a akceptačné kritériá.
  • Implementation plan rozkladá prácu na kontrolovateľné kroky.
  • ADR a standards sú kanonický zdroj rozhodnutí.
  • Agent má rozhodnutia zachytávať stručne a odkazovať na existujúce dokumenty, nie duplikovať text.

Čo si odniesť

Stack je dôležitý, ale ešte dôležitejší je spôsob práce

Malý rez

Začať jedným funkčným scenárom a overiť celé prepojenie.

Jasné hranice

Oddeliť zdroje dát, aplikačný model, API, UI a infraštruktúru.

Priebežná kvalita

Testy, observability a CI/CD zavádzať postupne, ale vedome.
